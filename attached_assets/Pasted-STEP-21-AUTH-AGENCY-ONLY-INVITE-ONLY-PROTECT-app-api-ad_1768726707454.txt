GOAL
Secure the dashboard and admin APIs with Clerk.
This is NOT a self-serve SaaS. We do NOT want public sign-up.
We want:
- Sign-in only
- Invite-only users (managed in Clerk dashboard)
- /app/* protected
- /api/admin/* protected
- Keep public widget + public APIs working (/widget/* and /api/public/*)

NON-NEGOTIABLES
- DO NOT add a public sign-up flow/route.
- DO NOT expose any admin API key to the browser.
- DO NOT break existing E2E tests (revenue loop).
- Must pass: pnpm lint, pnpm typecheck, pnpm test:e2e, pnpm build.
- Keep existing routes working: /, /pricing, /request-demo, /widget/[botPublicKey].

Next.js App Router + TypeScript strict is already set up.

5) MODIFY: Admin API routes to require auth
Files:
- src/app/api/admin/bots/route.ts
- src/app/api/admin/bots/[botPublicKey]/route.ts
- src/app/api/admin/seed/route.ts

Replace the current “same-origin bypass / x-admin-key” scheme with Clerk auth.
Implementation requirement:
- Use Clerk server auth in route handlers:
  - import { auth } from "@clerk/nextjs/server"
  - const { userId } = auth()
  - if (!userId) return NextResponse.json({ok:false,error:"unauthorized"},{status:401})
This makes admin APIs accessible only when the browser has a valid Clerk session cookie.

DO NOT change any /api/public routes.
