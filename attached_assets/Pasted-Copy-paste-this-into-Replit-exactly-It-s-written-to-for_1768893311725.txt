STEP 38B — API IMPLEMENTATION

2) Create API route: src/app/api/org/settings/services/route.ts

Implement handlers: GET, POST, PUT, DELETE.

Shared requirements:
	•	const ctx = await getOrgContext({ testUserId: getTestUserId(req) });
	•	If !ctx.ok, return { ok:false, error, message } with ctx.status.
	•	Load org allowClientEdits from DB (or include in ctx if ctx already selects it; do NOT trust stale values).
	•	Define:
	•	const canEdit = isAdmin(ctx.role) || (ctx.role === "CLIENT" && org.allowClientEdits);

GET
	•	Returns list of services for org, ordered:
	•	displayOrder asc, id asc
	•	Response shape:

{ "ok": true, "services": [ ... ] }

POST (create)
	•	RBAC: require canEdit === true else 403
	•	Validate body with Zod:
	•	name: required string, trim, min 2, max 80
	•	priceCents: optional int >= 0
	•	bookingUrl/paymentUrl: optional valid URL
	•	displayOrder: optional int >= 0
	•	isActive: optional boolean
	•	Duplicate prevention:
	•	Must reject if another service in same org has same name ignoring case.
	•	Return 409 { ok:false, error:"duplicate_service" }
	•	Create in Prisma with organizationId = ctx.org.id

PUT (update)
	•	RBAC: require canEdit
	•	Body includes id (or serviceId) + updatable fields validated with Zod.
	•	Must confirm service belongs to org before update:
	•	findUnique by id then verify organizationId matches ctx.org.id OR updateMany scoped by both id+organizationId.
	•	Duplicate name rule applies if name changes (case-insensitive check).
	•	Return updated service.

DELETE
	•	RBAC: require canEdit
	•	Must delete only if service belongs to org:
	•	use deleteMany({ where:{ id, organizationId: ctx.org.id }})
	•	If nothing deleted, return 404.

Status codes:
	•	200 OK for GET/PUT/DELETE success
	•	201 OK or 200 for POST (either ok)
	•	400 validation errors
	•	401/403 from ctx and RBAC
	•	404 for missing resource
	•	409 duplicate
	•	500 internal errors with console.error tags like [API] ...
