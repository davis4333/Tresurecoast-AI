## 📄 File Descriptions

### Core Implementation Files (REQUIRED)

#### `src/lib/booking/bookingFlowTypes.ts` (150 lines)
**Purpose**: Type definitions for entire state machine  
**Contains**:
- BookingFlowState enum
- BookingFlowContext interface
- ResponseDirective types
- Intent detection keywords
- Event type constants

**Why you need it**: Type safety for all booking flow operations

---

#### `src/lib/booking/bookingFlowValidators.ts` (180 lines)
**Purpose**: Validation functions for lead capture  
**Contains**:
- `validateName()` - 2-100 chars, letters/hyphens/apostrophes
- `validatePhone()` - 10-15 digits, normalizes formatting
- `validateEmail()` - RFC 5322 compliant, lowercases
- `looksLikeServiceSelection()` - Helper for detecting service picks

**Why you need it**: Ensures clean, valid lead data

---

#### `src/lib/booking/bookingFlowMachine.ts` (450 lines)
**Purpose**: Core state machine logic  
**Contains**:
- `initBookingContext()` - Creates fresh context
- `transition()` - Main state machine function (PURE)
- Intent detection helpers
- State transition handlers
- Global command handlers (cancel/restart/back)

**Why you need it**: This IS the booking flow engine

---

#### `tests/unit/bookingFlowMachine.test.ts` (400 lines)
**Purpose**: Comprehensive test coverage  
**Contains**:
- 60+ unit tests
- Intent detection tests
- Validator tests
- State transition tests
- Edge case tests
- Complete happy path test

**Why you need it**: Proves everything works before production
